    11. [Cours]: إدارة قواعد البيانات العلائقية باستخدام Spring Data

    الكلمات المفتاحية: بنية متعددة الطبقات، Spring، حقن التبعيات، API JPA (Java Persistence API)، Spring Data.

    سنقوم بتنفيذ الطبقة [DAO] من TD باستخدام [Spring Data]، وهو فرع من نظام Spring. يعتمد [Spring Data] على طبقة JPA (Java Persistence API) التي تسمح للطبقة [DAO] بمعالجة الكائنات بدلاً من الأوامر SQL. وفي النهاية، لا تدرك الطبقة [DAO] أنها تتواصل مع قاعدة بيانات. فهي لا تعرف سوى واجهة الطبقة [Spring Data].

    سنكتشف أولاً [Spring Data] من خلال مثالين.

    11.1. Support

    • في [1]، يحتوي المجلد [support / chap-11] على ثلاثة مشاريع Eclipse؛
    • في [2]، البرنامج النصي SQL الذي يسمح بإنشاء قاعدة البيانات النموذجية لهذا الفصل؛

    11.2. مثال 1

    يوجد على موقع Spring العديد من البرامج التعليمية للبدء مع Spring [http://spring.io/guides]. سنستخدم أحدها لتقديم Spring Data. ونستخدم لهذا الغرض Spring Tool Suite (STS).

    • في [1]، نقوم باستيراد أحد البرامج التعليمية من [spring.io/guides]؛
    • في [2]، نختار البرنامج التعليمي [Accessing Data Jpa] الذي يوضح كيفية الوصول إلى قاعدة بيانات باستخدام Spring Data؛
    • في [3]، يتم اختيار مشروع تم تكوينه بواسطة Maven؛
    • في [4]، يمكن تقديم البرنامج التعليمي في شكلين: [initial] وهي نسخة فارغة يتم ملؤها باتباع البرنامج التعليمي أو [complete] وهي النسخة النهائية من البرنامج التعليمي. نختار هذه الأخيرة؛

    11.2.2. الطبقة [JPA]

    يتم الوصول إلى قاعدة البيانات من خلال طبقة [JPA]، Java Persistence API:

      

    التطبيق بسيط ويدير العملاء [Customer]. الفئة [Customer] هي جزء من الطبقة [JPA] وهي كما يلي:

    
package hello;

import javax.persistence.Entity;
import javax.persistence.GeneratedValue;
import javax.persistence.GenerationType;
import javax.persistence.Id;

@Entity
public class Customer {

    @Id
    @GeneratedValue(strategy = GenerationType.AUTO)
    private long id;
    private String firstName;
    private String lastName;

    protected Customer() {
    }

    public Customer(String firstName, String lastName) {
        this.firstName = firstName;
        this.lastName = lastName;
    }

    @Override
    public String toString() {
        return String.format("Customer[id=%d, firstName='%s', lastName='%s']", id, firstName, lastName);
    }

}

    يحتوي العميل على معرف [id]، واسم أول [firstName]، واسم عائلة [lastName]. تمثل كل مثيل [Customer] سطرًا في جدول قاعدة البيانات.

    • السطر 8: تعليق توضيحي JPA الذي يجعل استمرارية مثيلات [Customer] (إنشاء، قراءة، تحديث، حذف) تُدار بواسطة تطبيق JPA. وفقًا لتبعيات Maven، نرى أن التنفيذ JPA / Hibernate هو المستخدم؛
    • السطران 11-12: تعليقات توضيحية JPA تربط الحقل [id] بالمفتاح الأساسي لجدول [Customer]. يشير السطر 12 إلى أن التنفيذ JPA سيستخدم طريقة إنشاء المفتاح الأساسي الخاصة بـ SGBD المستخدم، وهو هنا H2؛

    لا توجد تعليقات توضيحية أخرى لـ JPA. سيتم عندئذٍ استخدام القيم الافتراضية:

    • ستحمل جدول [Customer] اسم الفئة، أي [Customer]؛
    • ستحمل أعمدة هذا الجدول أسماء حقول الفئة: [id, firstName, lastName] مع العلم أن الأحرف الكبيرة والصغيرة لا تؤخذ في الاعتبار في اسم عمود الجدول؛

    تجدر الإشارة إلى أنه لم يتم تسمية التنفيذ JPA المستخدم في أي وقت من الأوقات.

    11.2.3. الطبقة [Spring Data]

    تنفذ الفئة [CustomerRepository] طبقة الوصول إلى الجدول [Customer]. وفيما يلي كودها:

      
    
package hello;

import java.util.List;

import org.springframework.data.repository.CrudRepository;

public interface CustomerRepository extends CrudRepository<Customer, Long> {

    List<Customer> findByLastName(String lastName);
}

    وبالتالي فهي واجهة وليست فئة (السطر 7). وهي توسع واجهة [CrudRepository]، وهي واجهة Spring Data (السطر 5). يتم تعيين هذه الواجهة بواسطة نوعين: الأول هو نوع العناصر المدارة، وهو هنا النوع [Customer]، والثاني هو نوع المفتاح الأساسي للعناصر المدارة، وهو هنا النوع [Long]. واجهة [CrudRepository] هي كما يلي:

    
package org.springframework.data.repository;

import java.io.Serializable;

@NoRepositoryBean
public interface CrudRepository<T, ID extends Serializable> extends Repository<T, ID> {

    <S extends T> S save(S entity);

    <S extends T> Iterable<S> save(Iterable<S> entities);

    T findOne(ID id);

    boolean exists(ID id);

    Iterable<T> findAll();

    Iterable<T> findAll(Iterable<ID> ids);

    long count();

    void delete(ID id);

    void delete(T entity);

    void delete(Iterable<? extends T> entities);

    void deleteAll();
}

    تحدد هذه الواجهة العمليات CRUD (إنشاء – قراءة – تحديث – حذف) التي يمكن إجراؤها على نوع JPA T:

    • السطر 8: تسمح طريقة save بحفظ كيان T في قاعدة البيانات. وهي تجعل الكيان محفوظًا بالمفتاح الأساسي الذي أعطاه له SGBD. كما تسمح بتحديث كيان T المحدد بمفتاحه الأساسي id. يتم اختيار إحدى العمليتين وفقًا لقيمة المفتاح الأساسي id: إذا كانت قيمته null، تتم عملية الحفظ، وإلا تتم عملية التحديث؛
    • السطر 10: نفس الشيء ولكن بالنسبة لقائمة من الكيانات؛
    • السطر 12: تسمح الطريقة findOne بالعثور على كيان T محدد بواسطة مفتاحه الأساسي id؛
    • السطر 22: تسمح الطريقة delete بحذف كيان T محدد بواسطة مفتاحه الأساسي id؛
    • السطور 24-28: متغيرات الطريقة [delete]؛
    • السطر 16: تتيح الطريقة [findAll] استرداد جميع الكيانات المخزنة T؛
    • السطر 18: نفس الشيء ولكن يقتصر على الكيانات التي تم تمرير قائمة معرفاتها؛

    لنعد إلى واجهة [CustomerRepository]:

    
package hello;

import java.util.List;

import org.springframework.data.repository.CrudRepository;

public interface CustomerRepository extends CrudRepository<Customer, Long> {

    List<Customer> findByLastName(String lastName);
}
    • السطر 9 يسمح بالعثور على [Customer] من خلال اسمه [lastName]؛

    وهذا كل شيء بالنسبة لطبقة [DAO]. لا توجد فئة لتنفيذ الواجهة السابقة. يتم إنشاء هذه الفئة عند التنفيذ بواسطة [Spring Data]. يتم تنفيذ أساليب واجهة [CrudRepository] تلقائيًا. أما بالنسبة للأساليب المضافة في واجهة [CustomerRepository]، فهذا يعتمد على الحالة. لنعد إلى تعريف [Customer]:

    
private long id;
private String firstName;
private String lastName;

    يتم تنفيذ الطريقة الموجودة في السطر 9 تلقائيًا بواسطة [Spring Data] لأنها تشير إلى الحقل [lastName] (السطر 3) في [Customer]. عندما يصادف Spring Data طريقة [findBySomething] في الواجهة المطلوب تنفيذها، فإنه ينفذها من خلال الاستعلام JPQL (لغة استعلامات Java Persistence) التالي:

    select t from T t where t.something=:value

    لذلك يجب أن يحتوي النوع T على حقل باسم [something]. وبالتالي فإن الطريقة

    List<Customer> findByLastName(String lastName);

    بواسطة كود يشبه ما يلي:

    return [em].createQuery("select c from Customer c where  c.lastName=:value").setParameter("value",lastName).getResultList()

    حيث يشير [em] إلى سياق الاستمرارية JPA. وهذا ممكن فقط إذا كانت الفئة [Customer] تحتوي على حقل باسم [lastName]، وهو ما يحدث بالفعل.

    في الختام، في الحالات البسيطة، يتيح لنا Spring Data تنفيذ الطبقة [DAO] بواجهة بسيطة.

    11.2.4. الطبقة [console]

      

    الفئة [Application] هي كما يلي:

    
package hello;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.CommandLineRunner;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class Application implements CommandLineRunner {

    @Autowired
    CustomerRepository repository;
    
    public static void main(String[] args) {
        SpringApplication.run(Application.class);
    }

    @Override
    public void run(String... strings) throws Exception {
        // حفظ عدد من العملاء
        repository.save(new Customer("Jack", "Bauer"));
        repository.save(new Customer("Chloe", "O'Brian"));
        repository.save(new Customer("Kim", "Bauer"));
        repository.save(new Customer("David", "Palmer"));
        repository.save(new Customer("Michelle", "Dessler"));

        // استدعاء جميع العملاء
        System.out.println("Customers found with findAll():");
        System.out.println("-------------------------------");
        for (Customer customer : repository.findAll()) {
            System.out.println(customer);
        }
        System.out.println();

        // استدعاء عميل فردي بواسطة ID
        Customer customer = repository.findOne(1L);
        System.out.println("Customer found with findOne(1L):");
        System.out.println("--------------------------------");
        System.out.println(customer);
        System.out.println();

        // استدعاء العملاء حسب الاسم الأخير
        System.out.println("Customer found with findByLastName('Bauer'):");
        System.out.println("--------------------------------------------");
        for (Customer bauer : repository.findByLastName("Bauer")) {
            System.out.println(bauer);
        }
    }

}
    • السطر 9: تنفذ الفئة الواجهة [CommandLineRunner] التي هي واجهة [Spring Boot] (السطر 4). لا تحتوي هذه الواجهة سوى على طريقة واحدة، وهي تلك الموجودة في السطر 19؛
    • السطر 8: @SpringBootApplication هو تعليق يجمع عدة تعليقات [Spring Boot]:
      • @Configuration: تشير إلى أن الفئة هي فئة تكوين؛
      • @EnableAutoConfiguration: يطلب من [Spring Boot] إنشاء عدد معين من الفاصوليا بنفسه بناءً على خصائص متنوعة، ولا سيما محتوى مسار الفئة (Classpath) للمشروع. نظرًا لوجود مكتبات Hibernate في مسار الفئات (Classpath)، سيتم تنفيذ حبة [entityManagerFactory] باستخدام Hibernate. نظرًا لوجود مكتبة SGBD H2 في مسار الفئات (Classpath)، سيتم تنفيذ الكائن (bean) [dataSource] باستخدام H2. في bean [dataSource]، يجب أيضًا تعريف المستخدم وكلمة المرور الخاصة به. هنا سيستخدم Spring Boot المسؤول الافتراضي لـ H2، وهو بدون كلمة مرور. نظرًا لوجود المكتبة [spring-tx] في مسار الفئات (Classpath)، فسيتم استخدام مدير معاملات Spring؛
      • @EnableWebMvc: إذا كانت مكتبة [spring-mvc] موجودة في مسار الفئات. في هذه الحالة، يتم إجراء تكوين تلقائي لتطبيق الويب؛
      • @ComponentScan: الذي يحدد لـ Spring مكان البحث عن الفاصوليا والتكوينات والخدمات الأخرى. هنا يتم البحث عنها افتراضيًا في الحزمة التي تحتوي على الفئة الموسومة، أي الحزمة [hello]. وبالتالي سيتم العثور على الفئتين [Customer] و [CustomerRepository]. ولأن الأولى تحمل التعليق التوضيحي [@Entity]، فسيتم تصنيفها ككيان يجب أن يديره Hibernate. ولأن الثانية تمتد واجهة [CrudRepository]، فسيتم تسجيلها كحبة Spring؛
    • السطران 11-12: يتم حقن bean [CustomerRepository] في كود الفئة الرئيسية؛
    • السطر 15: يتم تنفيذ الطريقة الثابتة [run] للفئة [SpringApplication] في مشروع Spring Boot. معلمتها هي الفئة التي تحتوي على تعليق توضيحي [Configuration] أو [EnableAutoConfiguration]. سيتم بعد ذلك تنفيذ كل ما تم شرحه سابقًا. والنتيجة هي سياق تطبيق Spring، أي مجموعة من الفاصوليا التي يديرها Spring؛

@Configuration
// @ComponentScan(basePackages={"package1","package2"})
public class AppConfig {

    // قاعدة البيانات H2
    @Bean
    public DataSource dataSource() {
        // مصدر البيانات TomcatJdbc
        DataSource dataSource = new DataSource();
        // تكوين الوصول JDBC
        dataSource.setDriverClassName("org.h2.Driver");
        dataSource.setUrl("jdbc:h2:./demo");
        dataSource.setUsername("sa");
        dataSource.setPassword("");
        // اتصال مفتوح في البداية
        dataSource.setInitialSize(1);
        // النتيجة
        return dataSource;
    }

    // المزود JPA
    @Bean
    public JpaVendorAdapter jpaVendorAdapter() {
        HibernateJpaVendorAdapter hibernateJpaVendorAdapter = new HibernateJpaVendorAdapter();
        hibernateJpaVendorAdapter.setShowSql(false);
        hibernateJpaVendorAdapter.setGenerateDdl(true);
        hibernateJpaVendorAdapter.setDatabase(Database.H2);
        return hibernateJpaVendorAdapter;
    }

    // EntityManagerFactory
    @Bean
    public EntityManagerFactory entityManagerFactory(JpaVendorAdapter jpaVendorAdapter, DataSource dataSource) {
        LocalContainerEntityManagerFactoryBean factory = new LocalContainerEntityManagerFactoryBean();
        factory.setJpaVendorAdapter(jpaVendorAdapter);
        factory.setPackagesToScan("entities");
        factory.setDataSource(dataSource);
        factory.afterPropertiesSet();
        return factory.getObject();
    }

    // مدير المعاملات
    @Bean
    public PlatformTransactionManager transactionManager(EntityManagerFactory entityManagerFactory) {
        JpaTransactionManager txManager = new JpaTransactionManager();
        txManager.setEntityManagerFactory(entityManagerFactory);
        return txManager;
    }

    • السطر 16: يشير التعليق التوضيحي [@Id] إلى أن الحقل [id] (قد يكون له اسم آخر) مرتبط بالمفتاح الأساسي لإحدى الجداول؛
    • السطر 17: تحدد التعليقات التوضيحية [@GeneratedValue(strategy=GenerationType.IDENTITY)] طريقة إنشاء المفاتيح الأساسية. سيستخدم الوضع [GenerationType.IDENTITY] مع MySQL الوضع [AUTO_INCREMENT]. مع SGBD آخر، سيستخدم هذا الوضع طريقة أخرى. الفائدة هي أن المطور لا يحتاج إلى القلق بشأن ذلك وأن كوده يظل صالحًا بغض النظر عن SGBD المستخدم؛
    • السطر 18: تشير التعليقات التوضيحية [@Column] إلى العمود المرتبط بالحقل. عندما لا تكون هذه التعليقات التوضيحية موجودة، يفترض JPA أن العمود يحمل نفس اسم الحقل. وهذا هو الحال هنا. لذلك كان من الممكن عدم وضع هذه التعليقات التوضيحية؛
    • السطر 20: يشير التعليق التوضيحي [@Version] إلى أن الحقل [version] مرتبط بعمود لإدارة الإصدارات. سيقوم التنفيذ JPA بزيادة رقم الإصدار هذا في كل مرة يتم فيها تعديل الكيان. يُستخدم هذا الرقم لمنع التحديث المتزامن للكيان من قبل مستخدمين مختلفين: يقوم مستخدمان U1 و U2 بقراءة الكيان E برقم إصدار يساوي V1. يقوم U1 بتعديل E ويحفظ هذا التعديل في قاعدة البيانات: عندئذٍ يتغير رقم الإصدار إلى V1+1. U2 يقوم بدوره بتعديل E ويحفظ هذا التعديل في قاعدة البيانات: سيتلقى استثناءً لأنه يمتلك إصدارًا (V1) مختلفًا عن الإصدار الموجود في قاعدة البيانات (V1+1)؛
    • الأسطر 35-52: إعادة تعريف الطرق [hashCode] و [equals]. بشكل افتراضي، تكون قيمة [obj1.equals(obj2)] هي true إذا كانت [obj1==obj2]، أي إذا كان ob1 و obj2 مؤشرين متساويين. إذا أردنا مقارنة الكائنات المشار إليها بدلاً من المؤشرات نفسها، يجب إعادة تعريف الطريقة [equals] والطريقة [hashCode]. يجب أن تعطي هذه الطريقة نفس القيمة لكائنين تعتبرهما الطريقة [equals] متساويين؛
    • الأسطر 42-51: سيُعتبر كائنان من النوع [AbstractEntity] أو مشتقان منه متساويين إذا كانت مفاتيحهما الأساسية [id] متساوية؛
    • الأسطر 35-38: تُرجع الطريقة [hashCode] بالفعل نفس القيمة لكائنين [AbstractEntity] متطابقين، وبالتالي لهما نفس المفتاح الأساسي [id]؛
    • الأسطر 55-63: تُرجع الطريقة [toString] السلسلة jSon للكائن [this]. إذا كان هذا الكائن يشير إلى فئة فرعية، فستُرجع هذه الطريقة سلسلة jSON الخاصة بالفئة الفرعية. وهذا يعفينا من إنشاء طريقة [toString] في الفئات الفرعية؛

    • السطر 25: يطلب السمة [fetch = FetchType.LAZY] أنه عند استرداد فئة من الجدول [CATEGORIES]، لا يتم استرداد منتجاتها على الفور. سيتم استردادها عند أول استدعاء للطريقة [getProduits]. لا تدير عمليات التنفيذ الحالية لـ JPA (Hibernate، Eclipselink، OpenJPA) هذه التعليقات التوضيحية بنفس الطريقة. يُثري Hibernate الطريقة [getProduits] الأولية (التي تكتفي بإرجاع الحقل produits) باستدعاء SGBD لجلب منتجات الفئة. ولكي يكون ذلك ممكنًا، يجب أن يكون الاتصال بـ SGBD المستخدم في البداية للحصول على الفئة لا يزال مفتوحًا. هذه الخاصية إلزامية. لا يمكن لتنفيذ JPA تجاهله. نظرًا لأن الخاصية [produits] قد تكون مبدئية أو غير مبدئية، فقد أدخلنا مرشح jSON في السطر 17 الذي سيسمح لنا بتحديد ما إذا كنا نريد هذه الخاصية أم لا؛
    • السطر 26: النوع [Set] هو واجهة. النوع [HashSet] هو فئة تنفذ هذه الواجهة. وهي تنفذ مجموعة من العناصر تسمى ensemble. لا يمكن أن تحتوي المجموعة على كائنين متطابقين. هنا، الكائنات من النوع [Produit]. وبالتالي، لا يمكن أن تحتوي المجموعة على كائنين متطابقين. نظرًا لأن الطريقة [equals] للفئة الأصلية [AbstractEntity] قد أعيد تعريفها لتشير إلى أن المنتجين متطابقان إذا كان لهما نفس المفتاح الأساسي، فإن الحقل [produits] لن يحتوي على منتجين لهما نفس المفتاح الأساسي؛
