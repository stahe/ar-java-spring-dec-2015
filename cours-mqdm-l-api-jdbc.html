    6. [Cours]: مقدمة إلى API JDBC

    الكلمات المفتاحية: قواعد البيانات العلائقية، API JDBC، SQLException.

    6.1. Support

    يحتوي المجلد [support / chap-06] على مشاريع Eclipse الخاصة بهذا الفصل.

    6.2. Architecture

    الطبقة JDBC (Java DataBase Connectivity) هي واجهة وصول عالمية إلى قواعد البيانات. وهي تقدم دائمًا نفس الواجهة للطبقة [DAO]. إذا تم تغيير SGBD، يكفي تغيير برنامج التشغيل JDBC. لا تتغير الطبقة [DAO].

    6.3. خطوات تشغيل قاعدة البيانات

    في البنية المذكورة أعلاه، يتضمن تشغيل قاعدة البيانات بواسطة برنامج وحدة التحكم الخطوات التالية:

    1. تحميل برنامج التشغيل JDBC لقاعدة البيانات؛
    2. فتح اتصال بالقاعدة؛
    3. إصدار أمر SQL على قاعدة البيانات ومعالجة نتائج الأمر SQL؛
    4. إغلاق الاتصال؛

    يتم تنفيذ الخطوة 1 مرة واحدة فقط. يتم تنفيذ الخطوات 2-4 بشكل متكرر. تجدر الإشارة إلى أنه لا يتم ترك الاتصال مفتوحًا. يتم إغلاقه بمجرد انتهاء الحاجة إليه.

    6.3.1. الخطوة 1 - تحميل برنامج التشغيل JDBC في الذاكرة

    الرمز

    
        // تحميل برنامج التشغيل JDBC
        try {
            Class.forName(nom de la classe du pilote JDBC);
        } catch (ClassNotFoundException e1) {
             // معالجة الاستثناء
}

    تهدف العملية الواردة في السطر 3 إلى تحميل برنامج التشغيل JDBC من قاعدة البيانات إلى الذاكرة. لا يلزم إجراء هذه العملية سوى مرة واحدة. ومع ذلك، فإن تكرارها لا يتسبب في حدوث أي خطأ. يتم البحث عن فئة برنامج التشغيل JDBC في مسار الفئات (Classpath) للمشروع. لذلك، يجب أن يكون ملف [jar] الذي يحتوي على فئة برنامج التشغيل JDBC قد أُدرج في مسار الفئات (Classpath) للمشروع في Eclipse.

    6.3.3. الخطوة 3 - إصدار الأوامر SQL [SELECT]

    بمجرد الحصول على اتصال، يمكن إصدار أوامر SQL. تختلف طريقة إدارة أوامر القراءة [SELECT] عن تلك المستخدمة في عمليات التحديث [UPDATE, INSERT, DELETE]. نبدأ بأوامر SQL [SELECT]:

    الرمز

    
Connection connexion = null;
        PreparedStatement ps = null;
        ResultSet rs = null;
        try {
            // بدء الجلسة
            connexion = DriverManager.getConnection(url, user, passwd);

            connexion.setAutoCommit(false);

            connexion.setReadOnly(true);

            System.out.println("Liste des produits : ");

    • السطران 8 و 10: فتح معاملة (السطر 8) في وضع القراءة فقط (السطر 10). المعاملة هي سلسلة من الأوامر SQL التي إما تنجح جميعها أو تفشل جميعها. وبالتالي، في معاملة تتضمن N أوامر SQL، إذا فشلت الأمر I+1، فسيتم إلغاء الأوامر I السابقة. بالنسبة لعملية القراءة، لا تكون المعاملة ضرورية. ومع ذلك، فإن إنشاء معاملة للقراءة فقط قد يسمح لبعض SGBD بإجراء بعض التحسينات؛
    • السطر 12: استخدام أمر [PreparedStatement]. عادةً ما يحتوي أمر [PreparedStatement] على معلمات يُشار إليها بالحرف "؟". هنا لا توجد معلمات. [PreparedStatement] هو أمر تم إعداده بواسطة SGBD. هذا الإعداد له تكلفة ولا يتم إلا مرة واحدة. بعد ذلك، يتم تنفيذ هذا الأمر المُعد بواسطة SGBD باستخدام معلمات فعالة مختلفة ستحل محل المعلمات الشكلية "؟". تجدر الإشارة إلى أنه من الأفضل تسمية الأعمدة المطلوبة بدلاً من استخدام الرمز * للحصول على جميع الأعمدة. من خلال تحديد أسماء الأعمدة، يمكن بعد ذلك الحصول على قيمها بناءً على موضعها في الاستعلام SELECT؛
    • السطر 13: تنفيذ [PreparedStatement]. يتم استرداد كائن من النوع [ResultSet]؛

    يمثل كائن من النوع [ResultSet] جدولًا، أي مجموعة من الصفوف والأعمدة. في لحظة معينة، لا يمكن الوصول إلا إلى صف واحد من الجدول يُسمى الصف الحالي. عند الإنشاء الأولي لـ [ResultSet]، لا يوجد صف حالي. يجب إجراء عملية [ResultSet.next()] للحصول عليه. توقيع طريقة next هو كما يلي:

        boolean next()

    تحاول هذه الطريقة الانتقال إلى السطر التالي من [ResultSet] وتُرجع true في حالة نجاحها، وfalse في حالة الفشل. في حالة النجاح، يصبح السطر التالي هو السطر الحالي الجديد. يتم فقدان السطر السابق ولا يمكن الرجوع للخلف لاستعادته.

    تحتوي جدول [ResultSet] على أعمدة تسمى labelCol1، labelCol2،... محددة في الاستعلام [SELECT] الذي تم تنفيذه. مع الاستعلام:

    SELECT ID as myId, NOM as myNom, CATEGORIE as myCategorie, PRIX as myPrix, DESCRIPTION as myDescription FROM PRODUITS
    • سيتم نقل العمود [ID] إلى عمود في [ResultSet] يسمى [myId]؛
    • سيتم نقل العمود [NOM] إلى عمود في [ResultSet] يسمى [myNom]؛
    • ...

    فيما سبق، يُطلق على المعرفات [myCol] اسم تسميات الأعمدة. وفي حالة عدم وجود هذه التسميات، فإن أسماء أعمدة [ResultSet] تعتمد على SGBD. عندما يعمل [SELECT] على جدول واحد، ستكون تسميات الأعمدة افتراضيًا هي أسماء الأعمدة المطلوبة بواسطة SELECT. تنشأ المشكلة عندما يعمل [SELECT] على عدة جداول وتوجد فيها أسماء أعمدة متطابقة كما في المثال التالي:

    SELECT PRODUITS.NOM, CATEGORIES.NOM FROM PRODUITS, CATEGORIES WHERE PRODUITS.CATEGORIE_ID=CATEGORIES.ID

    بافتراض أن الجدول [PRODUITS] يحتوي على مفتاح خارجي إلى الجدول [CATEGORIES] الذي يرمز إليه العلاقة [Produits].CATEGORIE_ID --> [CATEGORIES].ID، وأن الجدولين [PRODUITS] و [CATEGORIES] يحتويان كلاهما على حقل [NOM]. في هذه الحالة، تعتمد الأسماء المحددة في [ResultSet] للأعمدة [PRODUITS.NOM] و [CATEGORIES.NOM] على SGBD. للتنقل بين SGBD، يجب استخدام تسميات الأعمدة هنا وسنكتب:

    
SELECT PRODUITS.NOM as p_NOM, CATEGORIES.NOM as c_NOM FROM PRODUITS, CATEGORIES WHERE PRODUITS.CATEGORIE_ID=CATEGORIES.ID

    لاستخدام الحقول المختلفة في السطر الحالي لـ [ResultSet]، تتوفر الطرق التالية:

    Type getType("labelColi")

    للحصول على العمود المسمى «labelColi» من السطر الحالي، وبالتالي العمود في [SELECT] الذي يحمل هذا التسمية. يشير Type إلى نوع الحقل coli. يمكن استخدام الطرق التالية لـ [getType]: getInt، getLong، getString، getDouble، getFloat، getDate، ... بدلاً من استخدام اسم العمود، يمكن استخدام موضعه في الاستعلام [SELECT] الذي تم تنفيذه:

    Type getType(i)

    حيث i هو مؤشر العمود المطلوب (i>=1).

    6.3.4. الخطوة 3 - إصدار الأوامر SQL [INSERT, UPDATE, DELETE]

    الأوامر SQL [INSERT, UPDATE, DELETE] هي عمليات تحديث: فهي تُعدّل قاعدة البيانات ولكنها لا تُرجع أي سطر. والمعلومة الوحيدة التي تُرجع هي عدد الأسطر التي تأثرت بعملية التحديث.

    الرمز

    
Connection connexion = null;
        PreparedStatement ps = null;
        try {
            // فتح الاتصال
            connexion = DriverManager.getConnection(url, user, passwd);
            // بدء المعاملة
            connexion.setAutoCommit(false);
            // في وضع القراءة/الكتابة
            connexion.setReadOnly(false);
            // تحديث الجدول
            ps = connexion.prepareStatement("UPDATE PRODUITS SET PRIX=PRIX*1.1 WHERE CATEGORIE=?");
            // الفئة 1
            ps.setInt(1, 10);
            // التنفيذ
            int nbLignes=ps.executeUpdate();
            // تثبيت المعاملة
            connexion.commit();
        } catch (SQLException e1) {
            // معالجة الاستثناء
            doCatchException(connexion, e1);
        } finally {
            // معالجة finally
            doFinally(null, ps, connexion);
        }
    }
    • السطر 9: يتم استخدام الاتصال للقراءة والكتابة؛
    • السطر 11: [PreparedStatement] مع معلمة واحدة (يُرمز لها بـ؟). يمكن أن يكون هناك عدة معلمات. يتم ترقيمها بدءًا من 1؛
    • السطر 13: يتم تعيين قيمتها للمعلمة الوحيدة. المعلمة الأولى لـ [setType] هي موضع المعلمة في [PreparedStatement] (1، 2، ...) والثانية هي القيمة المخصصة لها. يمكن استخدام الطرق [setInt, setLong, setFloat, setDouble, setString, setDate, ...]؛
    • السطر 15: يتم استخدام الطريقة [executeUpdate] وليس [executeQuery] المخصصة لأوامر SELECT. تعرض الطريقة عدد الأسطر المتأثرة بالعملية. قد تكون 0.
    • السطر 17: يتم التحقق من صحة المعاملة؛

    6.3.5. الخطوة 4 - إغلاق الاتصال

    يجب إغلاق الاتصال في أسرع وقت ممكن في سياق متعدد المستخدمين لأن SGBD يقبل عددًا محدودًا من الاتصالات المفتوحة. في الأمثلة السابقة، تم إغلاقه في جملة [finally] لعمليات SQL بحيث يتم إغلاقه سواء حدثت استثناءات أم لا.

import java.util.List;

public class Static {

    public static List<String> getErreursFromThrowable(Throwable th) {
        // استرداد قائمة رسائل الخطأ الخاصة بالاستثناء
        List<String> erreurs = new ArrayList<String>();
        while (th != null) {
            // رسالة خطأ الكائن القابل للرمي

            // الانتقال إلى سبب الاستثناء
            th = th.getCause();
        }
        // النتيجة
        return erreurs;
    }

        // الرسائل

            System.out.println(String.format("- %s",message));
        }
    }

    6.4.7. حذف محتوى جدول المنتجات

    تقوم الطريقة [delete] بحذف محتوى الجدول:

    
// حذف المنتجات
    public static void delete() {
        Connection connexion = null;
        PreparedStatement ps = null;
        try {
            // فتح الاتصال
            connexion = DriverManager.getConnection(url, user, passwd);
            // بدء المعاملة
            connexion.setAutoCommit(false);
            // إفراغ الجدول [PRODUITS]
            ps = connexion.prepareStatement(delete);
            ps.executeUpdate();
            // تثبيت المعاملة
            connexion.commit();
            // العودة إلى الوضع الافتراضي
            connexion.setAutoCommit(true);
        } catch (SQLException e1) {
            // معالجة الاستثناء
            doCatchException("Les erreurs suivantes se sont produites à la suppression du contenu de la table", connexion, e1);
        } finally {
            // معالجة finally
            doFinally(null, null, connexion);
        }
    }

    يستخدم هذا المثال المعاملات. تسمح المعاملة بتجميع الأوامر SQL التي يجب أن تنجح جميعها أو تلغى جميعها. هناك أربع عمليات يجب معرفتها:

    • بدء معاملة: [connexion.setAutoCommit(false)]؛
    • نهاية معاملة ناجحة: [connexion.commit()]. في هذه الحالة، يتم التحقق من صحة جميع العمليات التي أجريت على BD أثناء المعاملة؛
    • نهاية معاملة فاشلة: [connexion.rollback()]. في هذه الحالة، يتم إلغاء جميع العمليات التي تمت على BD أثناء المعاملة؛
    • العودة إلى الوضع [auto-commit] وهو الوضع الافتراضي لـ API JDBC: [connexion.setAutoCommit(true)]. في هذا الوضع، تخضع كل أمر SQL لمعاملة. وبالتالي، إذا تم إجراء إدخالين وفشل الثاني:
      • في الوضع [AutoCommit=true]، يبقى الإدخال الأول (تمت المصادقة عليه بواسطة AutoCommit الأول)؛
      • في الوضع [AutoCommit=false]، يتم إلغاء الإدخال الأول؛

    في أمثلةنا، في كل مرة تحدث فيها استثناء، نقوم بإلغاء المعاملة في الطريقة [doCatchException]:

    
    private static void doCatchException(String title, Connection connexion, Throwable th) {
        // عرض رسائل الخطأ
        Static.show(title, Static.getErreursFromThrowable(th));
        // إلغاء المعاملة
        try {
            if (connexion != null) {
                connexion.rollback();
            }
        } catch (SQLException e2) {
            // عرض رسائل الخطأ
            Static.show("Erreur lors de l'annulation de la transaction", Static.getErreursFromThrowable(e2));
        }
}

    6.5. استخدام مصدر بيانات من النوع [DataSource]

    سنستأنف التطبيق السابق باستخدام مصدر بيانات من النوع [javax.sql.DataSource]:

    • عندما يغلق كود Java اتصالاً، يتم إرجاعه إلى المجموعة؛

    في النهاية، لا يتم فتح الاتصالات إلا مرة واحدة، مما يحسن أداء الوصول إلى قاعدة البيانات. سيتم تعريف مصدر البيانات في فئة تكوين Spring
